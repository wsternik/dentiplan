# Domain distillation

> A **map of the domain**, not code. Built from `context/foundation/prd.md`
> (39 numbered FRs, Business Logic, Access Control), `context/foundation/roadmap.md`,
> `docs/reference/contract-surfaces.md`, and the code itself. Nothing here is
> invented: every concept carries a source citation and either a code location
> or an explicit **NOT IN CODE**.

## 0. Context

**Product.** DentiPlan turns a dentist's semi-structured diagnosis note into two
comparable treatment-cost plans — a multi-visit standard plan and a single
session under general anaesthesia — and presents them to the patient side by
side at an unguessable link.

**Where business logic lives.** The stack is Astro 6 SSR + React 19 islands +
Supabase, deployed to Cloudflare Workers. There is **no domain layer**. Logic is
distributed across four places:

| Layer          | Path                                          | What it holds                                                           |
| -------------- | --------------------------------------------- | ----------------------------------------------------------------------- |
| Pure functions | `src/lib/quote/`, `src/lib/pricing/`          | the cost engine, the anaesthesia fee rule, tooth naming, token minting  |
| Service        | `src/lib/services/quote-payload.ts`           | the write-path contract and the approval guards                         |
| Routes         | `src/pages/api/`, `src/pages/*.astro`         | transaction orchestration; `approve.ts` is the only place state freezes |
| Database       | `supabase/migrations/…_quotes_foundation.sql` | immutability trigger, RLS, the patient-read RPC                         |

`evidence`. **Inference:** the domain is expressed as _types plus pure
functions_, not as objects with behaviour. That is a legitimate shape, and §5
argues it is the reason invariant I-1 is enforced in three places rather than
one.

**One structural fact that shapes everything below:** the entire quote is stored
as a single opaque `jsonb` column called `content`. No database constraint,
index or trigger inspects its interior (`evidence`, migration `:29` and the
absence of any expression index). Every rule about what is _inside_ a quote is
therefore an application-layer rule by construction.

## 2. Subdomains

| Subdomain                                                                                                        | Type                 | Why                                                                                                                                                                                                                                                                                                                |
| ---------------------------------------------------------------------------------------------------------------- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Two-variant cost comparison** (standard vs. anaesthesia, the fee rule, ranges, auto-skip of local anaesthesia) | **CORE**             | This _is_ the product. The PRD's insight is explicit: Polish practice-management systems target medical documentation, not patient-facing presentation, and "porównanie dwuwariantowych planów leczenia … jest niezagospodarowaną niszą". The anaesthesia fee is this practice's own rule and exists nowhere else. |
| **The frozen quote and its patient link** (approval, snapshot, token, immutability)                              | **CORE**             | It carries the product's two hardest promises: the price the patient sees is the price that was quoted (FR-050/FR-053), and only the link-holder can see it (FR-051/FR-066). Both are guardrails in the PRD, i.e. breaking them is defined as product failure.                                                     |
| **Diagnosis parsing**                                                                                            | CORE **but unbuilt** | The PRD names it as the second enabling insight — the reason the product is possible now. It is the ≤5-minute success criterion's main lever. Today the dentist fills the form by hand and S-02 is `blocked`.                                                                                                      |
| **Tooth taxonomy** (FDI numbering, names, dentition)                                                             | SUPPORTING           | Necessary and domain-specific, but a published standard, not this practice's advantage.                                                                                                                                                                                                                            |
| **Visit planning**                                                                                               | SUPPORTING           | Serves the standard variant; carries no rule of its own beyond partial sums.                                                                                                                                                                                                                                       |
| **Pricelist management**                                                                                         | SUPPORTING           | Deliberately minimal — seeded from JSON with no admin UI, an explicit scope cut.                                                                                                                                                                                                                                   |
| **Authentication & session**                                                                                     | GENERIC              | Delegated to Supabase; single operator, no roles.                                                                                                                                                                                                                                                                  |
| **Admin quote list**                                                                                             | GENERIC              | CRUD over the practice's own records.                                                                                                                                                                                                                                                                              |
| **Patient presentation**                                                                                         | SUPPORTING           | Carries one genuine domain rule — the non-dismissible estimate disclaimer (FR-065), a guardrail — but is otherwise rendering.                                                                                                                                                                                      |

## 3. Aggregate candidates and their invariants

| #        | Invariant (must always be true)                                                                                                                         | Source                 | Enforced?                                                                                                                                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **I-1**  | **An approved quote never changes.** Editing means a new quote, new snapshot, new token; the original stays intact and reachable by its original token. | FR-053                 | **Enforced, in three places.** DB trigger `quotes_immutable` on `OLD.status='approved'` (migration `:89-100`); endpoint scopes its UPDATE with `.eq("status","draft")` (`approve.ts:112`); UI hides mutating controls. |
| **I-2**  | **The price the patient sees is the price the server computed.** A client-sent price is never trusted.                                                  | FR-050                 | **Enforced structurally.** Items cross the wire as ids only and are re-resolved in `buildQuoteContent` (`quote-payload.ts:88-106`); totals recomputed at `approve.ts:91`.                                              |
| **I-3**  | **The patient page carries no identifying data.**                                                                                                       | FR-066, FR-072         | **Enforced structurally, twice.** `QuotePayloadSchema` has no e-mail slot, so nothing can nest one inside `content`; and the RPC whitelists four columns, none of them `patient_email` (migration `:117-123`).         |
| **I-4**  | **An approved quote always has a token and an approval timestamp.**                                                                                     | FR-051, FR-053         | **Enforced by the schema** — CHECK constraints `quotes_approved_has_token` / `_has_timestamp` (migration `:37-38`). This is why approval must be a single statement.                                                   |
| **I-5**  | **An invalid, unknown or draft token is indistinguishable from a valid one that does not exist.**                                                       | FR-060                 | **Enforced.** The RPC filters `status='approved'` and returns zero rows for everything else; the page renders one generic error. Probed by `e2e/patient-link-probe.spec.ts`.                                           |
| **I-6**  | **A quote is approved only by an explicit human click** — never automatically, whatever the parser's confidence.                                        | FR-013                 | **Declared, vacuously true.** There is no parser and no automation that could approve. The rule has nothing to guard against yet.                                                                                      |
| **I-7**  | **The estimate disclaimer is always present and cannot be dismissed.**                                                                                  | FR-065, guardrail      | **Enforced by construction** — `Disclaimer.astro` is rendered unconditionally with no dismiss affordance.                                                                                                              |
| **I-8**  | **No patient identifier ever reaches an external text-processing service.**                                                                             | Guardrail, FR-011      | **Vacuously true** — there is no external service call in the codebase. Becomes a live risk the moment S-02 is built.                                                                                                  |
| **I-9**  | **The patient token stays secret in transit.**                                                                                                          | FR-051, Access Control | **Partially enforced.** `Referrer-Policy: no-referrer` and `X-Robots-Tag` are set on the patient route; nothing else constrains where the dentist pastes the link.                                                     |
| **I-10** | **A quote's data is erased 12 months after creation.**                                                                                                  | NFR retention          | **NOT ENFORCED.** No retention job, no expiry column, no scheduled task. S-04 is `proposed`.                                                                                                                           |

## 4. Model-vs-code drift

The most valuable table in this document: where the domain the documents
describe and the domain the code implements are not the same domain.

| #       | The document says                                                                                                                                       | The code does                                                                                                                                                                            | Evidence                                                                                          | Reading                                                                                                                                                                                                                                                     |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **D-1** | The product's input is a **raw diagnosis note**, parsed into structured teeth (FR-010–FR-012); this is the insight that makes the product possible now. | There is a textarea (`QuoteEditor.tsx:355-362`) whose value is **never sent anywhere and never persisted**. Every tooth is entered by hand.                                              | `rawText` is island-local state; `treePayload()` (`:181-196`) does not include it.                | The product's headline capability does not exist. Deliberate and recorded — S-02 `blocked` — but it means the ≤5-minute success criterion is currently unmet by design. The strongest drift in the repo.                                                    |
| **D-2** | "On approval, the system captures a **snapshot of the active pricelist** permanently associated with the quote" (FR-050).                               | There is no snapshot entity. Each item is resolved and **copied by value** into the tooth that uses it, inside `content`.                                                                | `buildQuoteContent` (`quote-payload.ts:88-106`) maps ids to `resolvePricelistItem(id)` results.   | The _guarantee_ holds — later pricelist edits cannot move an approved quote. But the _concept_ has no representation: you cannot ask "which pricelist version was this quote priced from", only "what did each item cost". A version identifier is nowhere. |
| **D-3** | FR-060 distinguishes an "invalid, unknown, **or revoked**" token.                                                                                       | Nothing can revoke a token. There is no revoked state, no expiry column, and no code path that deactivates a link.                                                                       | `QuoteStatusSchema` has two values; no `revoked_at`; the RPC filters only on `status='approved'`. | A vocabulary word with no referent. Once minted, a link lives forever — which is also why D-4 matters.                                                                                                                                                      |
| **D-4** | Data retention: after 12 months the link returns the generic error and the patient's e-mail is erased.                                                  | Nothing expires. `quotes_created_at_idx` exists and its migration comment says it serves "the retention scan (S-04)" — an index built for a scan nobody wrote.                           | migration `:49`; roadmap S-04 `proposed`.                                                         | The only drift with a legal edge: the PRD frames retention under _ochrona danych osobowych_, and today every approved quote and every patient e-mail is kept indefinitely.                                                                                  |
| **D-5** | The token is a secret with an implied lifetime — one migration comment even reasons about "future-expired token".                                       | No expiry exists anywhere in schema or code.                                                                                                                                             | The RPC's header comment says an expired token "yields zero rows"; nothing computes expiry.       | Either the comment is stale or a feature was dropped without amending it. The history does not say which. A comment describing behaviour that does not exist is worse than no comment.                                                                      |
| **D-6** | Dentition (milk/permanent) is a first-class domain concept driving the anaesthesia base fee (FR-022, FR-042).                                           | `Dentition` is a bare `type` alias (`src/types.ts:46`), not a Zod schema — unlike every sibling concept (`ToothStatus`, `Urgency`, `TreatmentType`, all `z.enum`).                       | `src/types.ts:34-46`.                                                                             | Never validated at a boundary because it is always derived, never transmitted. Defensible — but it is the one domain concept the runtime cannot check.                                                                                                      |
| **D-7** | The business speaks of **kosztorys**, **zatwierdzenie**, **plan narkozowy**.                                                                            | The code has `Quote`, `content`, `approve.ts`, `totals.anesthesia` — and **"zatwierdzenie" exists only as a route filename**. There is no named operation, no `approveQuote()` function. | grep: no function in the repo is named for the act of approving.                                  | The domain's most important verb is spelled as an HTTP endpoint. This is the concrete reason invariant I-1 is enforced in three places instead of one — there is no single object that owns it (see 02).                                                    |
| **D-8** | The quote status vocabulary is one thing.                                                                                                               | The `draft`/`approved` enum is declared **three times**: `src/types.ts:26`, `src/pages/admin/index.astro:34` (a local re-declaration), and the migration's CHECK.                        | verified by grep across `src` and `supabase`.                                                     | Small, but it is the ubiquitous language failing literally: the same word defined in three dialects.                                                                                                                                                        |
| **D-9** | A tooth note is free text the dentist writes for the patient (FR-028), and the code caps it at 500 characters.                                          | The _visit label_ beside it — also patient-visible — is `z.string().default("")` with **no bound**.                                                                                      | `src/types.ts:118-121` vs `quote-payload.ts:46`; rendered at `VariantComparison.astro:21`.        | Two patient-visible free-text fields, one guarded and one not. The asymmetry looks accidental rather than reasoned.                                                                                                                                         |

## 5. Refactor ranking

Aggregate candidates ranked by **value** (how core the invariant is) against
**risk** (how weakly it is enforced today).

| Rank   | Aggregate             | Invariant                                | Core?                                                                | Enforcement today                                                                                                                           | Verdict                                                                                                                                                                                                              |
| ------ | --------------------- | ---------------------------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **#1** | **Kosztorys (Quote)** | **I-1 — an approved quote is immutable** | Highest. FR-053 is a guardrail; a breach is unrecoverable by design. | **Strong but scattered — three layers, no owner.** DB trigger + endpoint filter + UI. It works, and no single object is responsible for it. | **Refactor #1.** Not because it is broken — because its correctness currently depends on three unrelated mechanisms staying in agreement, and nothing tests the agreement. See `02-invariant-aggregate-refactor.md`. |
| #2     | Quote (write path)    | I-2 — server-authoritative prices        | High (FR-050)                                                        | Strong and structural, and unit-tested.                                                                                                     | Leave alone. It is the model of how to do this.                                                                                                                                                                      |
| #3     | Patient view          | I-3 — no identifying data                | High (FR-066, guardrail)                                             | Strong, twice over.                                                                                                                         | Leave alone.                                                                                                                                                                                                         |
| #4     | _(none)_              | I-10 — retention                         | Medium; legal                                                        | **Not enforced at all.**                                                                                                                    | Not a refactor — an unbuilt slice (S-04). Naming it here so it is not mistaken for a code smell.                                                                                                                     |

**Why #1 and not #2.** I-2's enforcement lives in one function that one module
owns, and it is tested. I-1's enforcement lives in a trigger, an endpoint filter
and a UI state, coordinated by nothing but the fact that one developer held all
three in mind on one afternoon. The research in
`context/changes/quote-approval-flow-analysis/research.md` shows the coordination
is already fraying: the endpoint half of it — `.eq("status","draft")` together
with the `.select("id")` that makes a zero-row match observable — **has no test
at all**, and the identical hole was found once before by a plan review, fixed,
and never pinned. That is the shape of an invariant about to be re-broken.

## 6. Limits of this document

- Built from the repository as of `main` at 2026-09-04. `unknown`: whether the
  deployed database schema still matches the migration text — the SQL probe that
  would confirm it is manual and not in CI, and this project has already had a
  three-month divergence between the two.
- FR coverage is read from the PRD and the roadmap, not from a running system.
  A requirement marked "enforced" here means the code implements it, not that it
  has been observed to work in production.
- Subdomain classification is a judgement against the PRD's stated vision and
  non-goals. Someone who read "the product is a quote generator" rather than
  "the product is a two-variant comparison" would rank the core differently, and
  the PRD's Vision section is the evidence for the reading taken here.
